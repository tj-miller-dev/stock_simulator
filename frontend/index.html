why it exists

no key, no signup

Your first request works from curl, from CI, from a coding agent — no account, no secrets, no rate-limit anxiety. 60 requests/minute per address, free.

deterministic

Identical requests return identical bars, forever. Seed your tests with reproducible fixtures; add &seed=anything for an alternate universe.

alpaca-compatible

Same paths, same params, same JSON shape as data.alpaca.markets. Real SDKs parse it without a single change. Markets closed? The simulation never is.

proof: same request, same bytes

Every bar is a pure function of (symbol, timestamp, seed). Below, the same request is fetched twice, live — compare the SHA-256 of the two response bodies. Yesterday's data never shifts under you, and neither will next month's re-run of your test suite.

use it from anywhere

curl 'https://cuckootrade.com/api/v2/stocks/bars?symbols=AAPL,CRASH&timeframe=1Day&start=2026-07-01'
from datetime import datetime

from alpaca.data.historical import StockHistoricalDataClient
from alpaca.data.requests import StockBarsRequest
from alpaca.data.timeframe import TimeFrame

client = StockHistoricalDataClient(
    api_key="any", secret_key="any",  # never checked
    url_override="https://cuckootrade.com/api",
)
bars = client.get_stock_bars(StockBarsRequest(
    symbol_or_symbols=["AAPL", "CRASH"],
    timeframe=TimeFrame.Day,
    start=datetime(2026, 7, 1),
))
print(bars["CRASH"][0])
const res = await fetch(
  'https://cuckootrade.com/api/v2/stocks/bars' +
  '?symbols=AAPL,CRASH&timeframe=1Day&start=2026-07-01'
)
const { bars } = await res.json()
console.log(bars.CRASH[0])
# server-sent events: an always-open synthetic session
curl -N 'https://cuckootrade.com/api/v1/stream?symbols=CUCKOO,CRASH'
